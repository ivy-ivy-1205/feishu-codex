# Ivy 与 James 的 Founder Stream 群聊使用说明

> 当前状态：这套交互已完成本地实现和测试，但尚未部署。真实群聊启用前，还需要完成生产语义适配器、变更审查，并由 Ivy 单独批准。

## 一句话说明

Ivy 和 James 继续在现有飞书群里正常讨论，不需要先判断属于哪个项目。机器人在后台整理话题、项目、双方理解和行动分歧，只在确实会影响推进时发卡片请两人确认。

## 平时怎么用

1. **正常聊天即可**：想法、项目进展、链接、文件和会议结论都继续发在同一个群里，不需要先立项、分群或每次 `@机器人`。
2. **机器人保持低打扰**：日常归类不会逐条回复。它主要发送两类卡片：
   - **工作地图**：把最近讨论整理为正在推进、候选项目、探索话题、想法、暂停事项和覆盖缺口。
   - **需要对齐**：只有双方对方向、下一步、负责人、时间或完成标准的理解不同，而且会影响行动时才提问。
3. **纠正时直接回复对应卡片**：不要脱离卡片单独发纠正。卡片里的编号只对当前这张工作地图有效。
4. **机器人记录纠正，不自动执行任务**：分类调整或达成共识只更新公司 Context；部署、发消息、改代码等动作仍需要 Ivy 明确授权。

## 工作地图怎么纠正

直接回复机器人发出的工作地图，例如：

- `2 和 4 是同一个项目`
- `第 1 项只是想法`
- `第 1 项改名为 客户知识库`
- `第 1 项改为探索中`
- `暂停第 1 项`
- `第 1 项拆分为 客户知识库 和 销售助手`

如果指代不清、编号过期或没有回复对应卡片，机器人会请你补充，不会自行猜测。

## 出现“需要对齐”时怎么回复

机器人会同时列出 Ivy 和 James 的原始理解，并且一次只问一个问题。

推荐做法：

1. 一个人在卡片下明确提出方案，例如：`按 A 方案推进`。
2. 另一人明确确认同一个方案，例如：`同意，按 A 方案推进`。
3. 机器人确认两边证据一致后，发送“已对齐”回执。

其他常用回复：

- `不用提醒`：关闭这次提醒，但不代表双方已经达成共识。
- `撤回刚才的方案，先不要推进`：撤回自己的旧支持，机器人不会继续把旧方案当成当前共识。

已读、`收到`、`晚点看`、沉默或带条件的表达不会被当成共同决定。

## 飞书会议与妙记

启用后，符合 Founder Stream 范围的飞书妙记会自动进入同一套话题与对齐系统，不需要手动复制妙记链接。会议总结仍按原流程发送；妙记只作为新的 Context 来源，不读取会议视频，也不会因为会议里生成了 Todo 就自动执行。

## 第一次启用时

1. 机器人先整理冻结的 20 天历史窗口，并生成第一版工作地图。
2. Ivy 和 James 集中纠正合并、拆分、命名和阶段。
3. 第一版确认后，机器人持续处理群内新增消息和符合范围的妙记。
4. 后续只有真正影响行动的未对齐事项才进入群提醒。

## 记住三个原则

- 不用先想“这属于哪个项目”，先把真实讨论留在群里。
- 纠正和对齐必须回复对应机器人卡片，让来源与对象可追溯。
- 机器人负责整理和暴露分歧，不代替 Ivy 与 James 做决定，也不自动执行工作。
