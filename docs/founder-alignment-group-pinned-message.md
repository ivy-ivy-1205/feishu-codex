# AiJia Context 群置顶说明

> 使用时机：每日一次游标式防漏复核部署并验证后，置顶到 Ivy 与 James 的唯一批准群。

📌 **AiJia Context｜群内使用与工作机制**

机器人会自动读取本群新增的文字和支持解析的文档，并完成五类工作：

- 从群聊和文件中动态识别项目；
- 判断信息是项目、原则、产物、研究还是想法；
- 区分 Ivy 和 James 的当前观点与历史观点；
- 判断“缺少表达”和“真实分歧”；
- 避免把沉默、旧意见或相似措辞误判成共识。

**它怎么工作**

消息到达后立即保存 → 同一话题安静约 5 分钟后批量分析 → 更新项目地图和双方理解。机器人默认保持安静，不说话不等于没有记录。每天还会从“上次完整复核到的位置”继续读取到当前时间；即使中断数天，也会补齐整个缺口，不只看最近 24 小时。读取不完整时不会前移游标，重复内容不会重复分析。

**怎么确认是否处理、有没有遗漏**

查询结果会显示最后收到消息、最后完成分析、最后防漏复核、待处理任务、失败及不可读缺口。已送达 Bridge 的消息会持久化并重试；读取不到的文件或消息会显示为缺口，不会被当作已经覆盖。

直接在群里发送以下指令，无需 `@机器人`：

- `查看工作地图`
- `查看对齐：项目名`
- `查看待对齐` 或 `查看分歧`

**「查看分歧」怎么处理**（2026-10-30 起）

- 真实分歧：两人或两方对同一件事写明了不同主张，双方都有原文出处。
- 待决定：Space 页面列了几个方案或待拍板的事，还没人表态。
- 等第三方确认、文件版本不一致这类事项算「卡点与问题」，不算分歧。
- 「真实分歧」和「待决定」的条目都有编号。直接回复这张卡片，可以多行，一行一条：
  - `第 2 条 已解决：按 A 方案`（或 `2 已解决`），移到「最近已解决」，标明谁记录；
  - `第 3 条 不是分歧`（待决定可写 `不用决定`），不再列出，原始记录保留。
- 一方回复「已解决」就算解决。Space 页面上的条目，只要那一段原文不变就不会再出现；页面改写了那一段，会重新判断。建议「已解决」的事也在 Space 页面补一句结论。
- Space 页面看不到是谁改的，写不同意见时请带名字，比如「James：…」「Ivy（10-28）：…」。

当前验证阶段只响应手动查询，不会自动推送地图或分歧提醒。验证准确后，只有影响方向、下一步、负责人、期限或完成标准的分歧才会触发自动提醒。机器人只整理 Context，不自动执行任务；未回复不等于同意。
