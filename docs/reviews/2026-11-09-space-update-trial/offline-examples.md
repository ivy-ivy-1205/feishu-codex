## 示例 A：Family First 历史日期保留

### 来源情境（基于 clarifications.md B 节）

旧句（11/3 after 及 11/4 before）：
> "A+C本地结构小样 · **10月29日**｜V4已有短欢迎、双主题、共享展示台、设计解释、统一记录、回顾与后续沟通预览；**进入完整路径评审**"

新句（11/4 after）：
> "A+C本地结构小样｜**V4完整结构保留，V5 UI另线推进；C餐厨正反两帧已通过**"

### 预期行为

新指引要求：「带日期历史保留事件—日期—状态关联，不用采集时间、整页修改时间或创建账号补事件日期和表达者；读回检查这些关系仍在。」

**正确做法**：更新应保留 10/29 V4 进入完整路径评审的原始日期关联，可采用：
```
A+C本地结构小样 · 10月29日 V4进入完整路径评审｜V4完整结构保留，V5 UI另线推进；C餐厨正反两帧已通过（11/3记载餐厨通过，11/4 KF03返修）
```

**应避免**：
- 用 11/4 的采集时间覆盖 10/29 的事件日期
- 删除「10月29日」「进入完整路径评审」关联
- 混淆 V5 与 V4 的时间线，误判 V5 全盘替代 V4

### 读回检查项

- [ ] 10/29 日期仍与 V4 评审关联
- [ ] V4/V5 分线清晰
- [ ] 11/3 餐厨通过与 11/4 KF03 返修是分开的事件组

## 示例 B：明确替代的规则变更

### 来源情境

假设存在一条已确认的历史调度规则（需要实际来源确认）：
> "日报发送时间：北京时间 12:00"（生效期 10/15 起）

后续变更（假设存在确认来源）：
> "日报发送时间调整为北京时间 18:00"（11/4 生效）

### 预期行为

新指引要求：「明确替代保留旧判断的历史身份、日期和来源」

**正确做法**（如有可查确认来源）：
```
日报发送时间：北京时间 18:00（11/4 起生效）
  - 此前为北京时间 12:00（10/15 至 11/3）
```

**限制说明**：
- 本示例仅为格式演示
- 未找到原始确认来源时，不能捏造「Ivy 已确认」
- 如果调度变更的原始授权不可查，应标注「来源待确认」而非假设存在

## 示例 C：Smart Listing 查询交付，不关闭账号边界议题

### 来源情境（基于 clarifications.md C 节）

新交付：

页内相关旧判断：
> "账号边界议题：正式客户身份/权限/审计问题待确认"

### 预期行为

新指引要求：「新提案或疑似冲突不覆盖已定决定，不自动关闭或升格为共识，不自动创建待确认编号」

**正确做法**：
```
Smart Listing
- v9 新增 Amy 查询本家庭问题答复（已上线）
- 账号边界议题仍在（正式客户身份/权限/审计问题）
```

- 仅因功能可查询就关闭账号边界议题
- 将「能查询」升格为「账号边界问题已解决」
- 自动为该议题创建待确认编号

### 读回检查项

- [ ] 新功能交付正确记录
- [ ] 账号边界议题明确标注「仍在」
- [ ] 未出现自动关闭或升格
