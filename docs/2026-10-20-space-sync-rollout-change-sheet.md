## 上线步骤

### S0｜真实页面只读试点（不改生产）

1. **导出：** 你在 Codex App 用我提供的提示词，只读 Smart Listing 页面，导出 envelope JSON（正文 blocks、评论、作者 ID、线程状态、覆盖情况），发给我。
2. **本地校验：** 我只输出统计，不展示正文：
   - schema 是否通过；
   - blocks 和评论的数量；
   - 是否读完整，有哪些缺口；
   - 有哪些作者 ID。
3. **生产副本预览：** 在生产数据库的只读副本上，先登记映射、再导入、再跑一次 Space 分析，生成对比预览（Grove 一张图加文字卡）。
   - Space 分析要用 Codex，**要等额度恢复**。
4. **你审阅：** 项目归属、本周进展、评论分别算谁的看法、有没有被误判成共识。

门禁：副本前后哈希一致；生产数据库、开关和镜像都不变；没有群消息。

### S1｜发版并开启接收（生产）

1. 按以往流程发版 C1–C3，门禁和回滚资产照旧。
2. **密钥：** 在服务器生成 HMAC 密钥文件 `/opt/feishu-codex/secrets/space-sync-hmac`，权限 600。值不显示，也不写进仓库或记录。
3. **开关：** 设置 `SPACE_SYNC_INGEST_ENABLED=true`，其余两个仍为 false，重启 Bridge。
4. **登记：** 用 `register-space-mapping --apply --change-ref <本变更单>` 只登记 Smart Listing 这一页，以及你确认过的作者。
5. **导入：** 用 `import-space-sync` 导入 S0 那份 envelope。

门禁：
- 接收入口只能从本机访问，nginx 没有转发它；
- 数据库完整；
- 只多出 1 个页面绑定和本次的来源记录；
- Space 分析任务只排队、不执行；
- 工作地图预览与发版前完全一致。

### S2｜开启分析（生产，影子阶段）

1. 等 Codex 额度恢复后，设置 `SPACE_SYNC_ANALYSIS_ENABLED=true`，重启 Bridge。
2. 排队的 Space 分析任务执行，生成页面摘要和评论观点。

门禁：
- 分析成功、没有失败重试；
- 摘要的每一条都能在原文里逐字找到；
- 有了 C1，工作地图、项目进展和处理状态的输出与开启前完全一致。

### S3｜开启展示（生产）

1. 设置 `SPACE_SYNC_WORKMAP_ENABLED=true`，重启 Bridge。
2. 你发一次「查看工作地图」和「查看项目进展：Smart Listing」，作为唯一一次人工验收。

门禁：
- Smart Listing 卡片出现页面摘要、本周进展和 Space 新鲜度；
- 其他条目和编号不变；
- 没有自动群消息。

### S4｜之后另走变更单

- 接入 Family First 和「超级个体到超级团队」。
- 自动同步（T2）：由你本机的 Codex App 定时任务读取并提交。它依赖你的电脑在线，状态里要标成本机运行。
  - 要走网络提交，还需要另外决定是否在共享 nginx 上开放接收入口。

## 回滚

- **S1–S3：** 把对应开关改回 false 并重启，Space 内容立即从所有视图消失，飞书侧功能不受影响。已导入的来源保留，不删除。
- **发版：** 照旧保留回滚镜像、app 快照和停机时的数据库备份，任一门禁失败自动回滚。
- **登记或导入出错：** 用切换前的数据库备份恢复。这一步只在你同意后执行。

## 不做

- 不扫描整个 Space，只读登记过的页面。
- 不反向修改 Space 页面。
- 不让 Space 内容新建、改名或改阶段工作地图条目，只补充已登记的条目。
- 不把评论自动当成共识。
- 不发群消息，不执行 Todo，不接 API Key，不保存 ChatGPT 登录态。

## 风险

- **额度：** Codex 额度未恢复时，S0 第 3 步和 S2 都做不了；C1–C3 和 S1 不受影响。
- **导出可靠性：** 页面导出依赖你手动在 Codex App 操作，首期只适合低频同步。真正的自动同步要等 S4。
- **页面结构：** Space 页面由多人和多个 AI 局部编辑，没有固定结构，摘要质量要靠 S0 的预览来判断。
