# James，对齐室复用说明｜2026 年 10 月 26 日

建议复用现有机器人、共同资料账本和 Space 页面，不另搭一套。

## 1. 现在是怎么连起来的，关机后会怎样？

目前有两条链路，最后都进入同一个 Context 共同资料账本：

- **飞书 → 服务器上的 Bridge → Codex CLI 整理 → Context → 飞书查询卡片和白板。**
  - 这条链路运行在腾讯云服务器上，不依赖 Ivy 的电脑开着。
- **Space 页面 → Context。**
  - 服务器端已能接收自动同步。合伙人对齐室这一页已试跑通过，另外三页暂时仍是人工同步：Ivy 导出页面 Markdown，再导入服务器。
  - Space 刚改完，不代表飞书已经读到。
  - 这一段正在改成自动同步，见下面「Space 自动同步」。

服务器上的 Codex CLI 读不到 Space。Space 要用 Ivy 的 ChatGPT 账号访问，而服务器按规定不保存这个登录信息。Codex CLI 只负责分析已经提交到服务器的页面内容。Space 页面由 Ivy 本机的 Codex 通过 Pages 工具读取。

### Space 自动同步（试跑中）

**做法**
1. Ivy 本机的 Codex App 每天北京时间 9:00 读取一次已登记的页面。
2. 读到的正文通过一把专用提交钥匙交给服务器。这把钥匙只能提交已登记项目的页面正文，不能登录服务器，也不能执行其他操作。
3. 服务器把正文存成新版本，和人工导入走同一个流程，进入同一个 Context。
4. 页面没有变化时，服务器只刷新「Space 页面最后同步」的时间，不会重复生成摘要。页面有变化时，服务器上的 Codex CLI 重新生成该项目的摘要，工作地图、项目进展和分歧随之更新。

整个过程不需要公网接收入口，不需要改服务器的网络配置，也不需要共享任何人的账号或密码。

**进度**
- **10 月 25 日，读取能力验证通过：**
  - Ivy 本机的 Codex 能读到四个页面的完整正文和系统修改时间。
  - 自动读到的正文和人工导出的版本逐字一致。
  - 连续读两次，没有误报变化。
- **10 月 26 日，首次无人值守读取：** 每天北京时间 09:00 的只读观察任务读到了四页正文和评论。但保存观察记录时被本机写入权限拦住，这个问题要在开启每日自动提交前解决。
- **10 月 26 日，服务器端上线并试跑：**
  - 接收程序已按原流程上线（隔离预检、备份、可回滚）。
  - 专用钥匙已安装，实测它不能执行命令、不能登录，也不能提交名单之外的页面。
  - 用它提交「AiJia 合伙人对齐室项目总览」：第一次生成新版本，摘要自动更新；第二次内容没变，只刷新了同步时间。
  - 全程没有向飞书群发送任何消息。
- **下一步：**
  - Ivy 在 Codex App 里允许每日任务写入本机文件夹、连接服务器，并把任务改成「读取后提交」，先只提交对齐室这一页。
  - 稳定几天后，再加入另外三页。

**限制**
- Ivy 的电脑睡眠、关机，或 Codex App 没开时，同步会暂停。卡片底部的「Space 页面最后同步」会如实显示上次同步的时间；某天 9:00 那次没跑成、距上次同步超过 24 小时，就标为过期，不会把旧内容当成最新的。
- 评论暂不进入同步。评论能读到，但「评论由谁表达、能否代表个人判断」还没定。
- 只同步已登记的页面，不会扫描整个 Space，也不会反向修改 Space。

## 3. 怎样看最近处理到哪里？

## 4. 你的 Codex 要复用，需要做什么？

先做一次最小试跑：

1. **确认 Space 权限。**
   - 用你自己的 ChatGPT 账号打开上面四个链接。
   - 打不开的页面，请页面所有者在页面右上角「分享」里邀请你的账号：只看给查看权限，需要改正文才给编辑权限。
   - 不需要共享 Ivy 的账号、密码或 token。
2. **确认你的 Codex 能读页面。**
   - 把链接交给它，先只让它读正文和评论，并报告内容是否完整、有没有权限缺口。
   - 如果你的环境里没有 Pages 工具，先用页面导出的 Markdown。有页面权限，不等于每个 Codex 环境都装了连接工具。
3. **复用现有飞书查询。**
   - 在群里发「查看工作地图」「查看项目进展：项目名」「查看分歧」「查看处理状态」，把结果交给你的 Codex。
   - 目前还没验证你的个人 Codex 能不能直接读现有的 Bridge 和 Context，所以先用这个办法。不需要申请服务器权限，也不需要另建机器人。
4. **你改了 Space 页面，怎么进飞书？**
   - 你直接改已登记的页面就行，不用自己导出或提交。
   - 已接入自动同步的页面，Ivy 本机的同步任务会在下一个 9:00 读取时带上你的修改；急需更新时告诉 Ivy 手动同步一次。
   - 还没接入的页面，请告诉 Ivy 哪一页改了，由她导出导入。
   - 请不要让你的 Codex 另外向服务器提交页面。同步入口只保留一个，避免两边各维护一套、出现两个版本。
5. **先核对一份日报，再考虑每天自动执行。** 日报固定三栏，每条都保留来源和时间：
   - ① Ivy 新完成了什么；
   - ② 哪些事明确在等 James；
   - ③ James 已完成、需要同步给 Ivy 的事项。

   只记在你私人工作记录里的成果，需要你提供或写进共享页面，系统不能凭空知道。

你可以直接把下面这段要求交给你的 Codex：

```text
根据我有权访问的四个 Space 页面、我提供的飞书查询结果和我的个人完成记录，整理上述三栏日报。
没有明确负责人或明确请求的，不要推断成「在等 James」；一方没有表态，不算同意，也不算分歧。
更新 Space 前，先给出具体要改的内容，经我确认后再写入；保留来源、历史和他人的意见。
页面写入成功后，标记「待同步飞书」，等飞书卡片底部的「Space 页面最后同步」时间晚于写入时间，再确认两边一致；不要提前声称两边已经一致。
```
